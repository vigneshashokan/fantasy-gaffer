# Accessibility

This document standardizes the accessibility conventions (a11y) used throughout Fantasy Gaffer and documents the manual validation procedures for screen reader support, reduced motion, and large text sizes.

## Conventions

All interactive controls must declare their role and state explicitly for assistive technologies (VoiceOver on iOS, TalkBack on Android). The table below summarizes the required `accessibilityRole`, `accessibilityState`, `accessibilityLabel`, and other props for each control type:

| Control Type | Required Props | Notes |
|--------------|---|---|
| **Text button** | `accessibilityRole="button"` | Named by the button's visible text; no explicit label needed. |
| **Icon-only button** | `accessibilityRole="button"` + `accessibilityLabel="<action>"` | Icon alone is not descriptive; must provide an explicit label (e.g. "Close", "Menu", "Search"). |
| **Toggle / switch** | `accessibilityRole="switch"` + `accessibilityState={{ checked }}` + `accessibilityLabel="<label>"` | State must be declared so screen readers announce "on" / "off". |
| **Tab** | `accessibilityRole="tab"` + `accessibilityState={{ selected }}` + label text or `accessibilityLabel` | Announce which tab is active. Parent container should have `accessibilityRole="tablist"`. |
| **Inline text link** | `accessibilityRole="link"` on the `Text` span | Allows screen readers to navigate links via tap or link-rotor. |
| **Status banner / form error** | `accessibilityLiveRegion="polite"` or `"assertive"` + `useA11yAnnounce(message)` | Use `polite` for status updates (e.g. "Fixtures loaded"); `assertive` for errors or urgent messages. |
| **Fixed-height control text** (buttons, pills, tab bar) | `maxFontSizeMultiplier={MAX_FONT_SCALE}` | Prevents text overflow in large Dynamic Type sizes; set only on controls with fixed heights; body/content text remains uncapped. |
| **Decorative view** (icons with no meaning, spacers, dividers) | `accessibilityElementsHidden={true}` + `importantForAccessibility="no-hide-descendants"` | Hides the view from the accessibility tree without hiding its children; allows child text to remain announced. |

## Primitives

Four utilities are exported from `@/lib/a11y` to streamline accessible patterns:

### `MAX_FONT_SCALE`
A constant (`1.4`) that caps text scaling in fixed-height controls (buttons, pills, tab bar) to prevent clipping when users enable **large Dynamic Type** sizes. Apply it via `maxFontSizeMultiplier={MAX_FONT_SCALE}`. Body text and content sections remain uncapped.

```tsx
import { MAX_FONT_SCALE } from '@/lib/a11y';

<Pressable accessibilityRole="button" accessibilityLabel={label}>
  <Text maxFontSizeMultiplier={MAX_FONT_SCALE}>
    {label}
  </Text>
</Pressable>
```

### `useReducedMotion()`
A hook that returns `boolean` — `true` when the OS **Reduce Motion** accessibility setting is enabled. Defaults to `false` on first paint; resolves asynchronously. Use it to skip animations, fade instead of slide, or render static skeleton pulses.

```tsx
import { useReducedMotion } from '@/lib/a11y';

function GameweekCarousel() {
  const isMotionReduced = useReducedMotion();
  
  return (
    <Animated.View
      style={{
        transform: [{ translateX: isMotionReduced ? 0 : animValue }],
      }}
    >
      {/* content */}
    </Animated.View>
  );
}
```

### `announce(message: string)`
An imperative function that announces a message to the screen reader immediately. Use it for one-off announcements that don't tie to a visible element (e.g. a background sync result). Prefer `useA11yAnnounce` for reactive announcements tied to state changes.

```tsx
import { announce } from '@/lib/a11y';

const handleRefresh = async () => {
  try {
    await refetch();
    announce('Data refreshed');
  } catch (e) {
    announce('Failed to refresh: ' + e.message);
  }
};
```

### `useA11yAnnounce(message: string | null | undefined)`
A hook that announces `message` to the screen reader whenever it changes to a new non-empty value. Pair it with a visible element that has `accessibilityLiveRegion` set (Android requires the live region on the visible element; iOS uses the imperative `announce` under the hood). Use this for status/error messages driven by state.

```tsx
import { useA11yAnnounce } from '@/lib/a11y';

function PickList({ error, isLoading }: Props) {
  // Pass a string when there's something to announce, otherwise null —
  // the hook's message type is `string | null | undefined`.
  useA11yAnnounce(error ? `Error: ${error.message}` : null);

  return (
    <View
      accessible={true}
      accessibilityLiveRegion="polite"
      accessibilityLabel={isLoading ? 'Loading' : 'Picks'}
    >
      {/* content */}
    </View>
  );
}
```

## Manual Validation Checklist

The automated test suite (jest) cannot exercise screen reader behavior, reduced-motion preferences, or dynamic text scaling on actual devices. The following checklist covers on-device validation required to ship accessible code.

Run each check on a real device (iOS and Android where noted; Web = macOS/Linux Lighthouse):

- [ ] **VoiceOver (iOS) walk-through**: Pair an iPhone with VoiceOver enabled (Settings → Accessibility → VoiceOver → On). Walk through the main flow: onboarding slides → sign in → connect team → each tab (Top Picks / My Team / Transfer) → account menu → settings → profile → player detail → sign out. For each screen:
  - Every interactive control is announced with a sensible `accessibilityRole` + name/label (e.g. "Sign in, button"; "FDR, tab, selected").
  - Focus order is logical and follows the visual left-to-right, top-to-bottom reading order.
  - Modals trap focus; swiping backward at the last control wraps to the first.
  - Large text (Dynamic Type max size) remains readable; buttons and pills do not clip.
  - No placeholder text reads as the label (e.g. "Email address" button should not read "Email").

- [ ] **TalkBack (Android) spot-check**: Enable TalkBack (Settings → Accessibility → TalkBack → On). Walk through the same main flow on an Android device. Confirm:
  - Interactive controls announce role + name (e.g. "Connect team, double tap to activate").
  - Focus order is logical.
  - Status messages and errors are announced via `accessibilityLiveRegion` (e.g. "Error: Invalid email").
  - Swipe right/left navigation works smoothly between controls.

- [ ] **Reduce Motion ON**: Enable Reduce Motion (Settings → Accessibility → Motion → Reduce Motion → On). Verify:
  - Skeleton pulse loaders are static (no pulse animation).
  - Gameweek pager and top-picks carousels jump to the next item without slide animations.
  - All transitions are instant or fade (no bounce/slide).

- [ ] **Large Dynamic Type**: Set font size to the **maximum accessibility size** (Settings → Accessibility → Display & Text Size → Larger Accessibility Sizes → pick the largest). Verify:
  - Button and pill text does not clip or overflow.
  - Tab bar labels remain fully visible.
  - All content remains readable; no layout breaks or overlaps.

- [ ] **Accessibility Inspector (Xcode)**: On a connected iOS device, run Xcode's Accessibility Inspector (Xcode → Window → Accessibility Inspector) on the main screens (Onboarding, Sign In, Team, Top Picks, Settings). Look for:
  - Missing `accessibilityLabel` on icon-only buttons or tab items.
  - Missing `accessibilityRole` on interactive elements.
  - Decorative elements that should be hidden from the tree (should have `accessibilityElementsHidden={true}`).
  - **Note:** contrast warnings (white text on light backgrounds, etc.) are handled in the separate **W7 contrast retune** PR, not here.

- [ ] **expo-web Lighthouse audit**: Build and serve a web version (`npm run web`), then run Lighthouse (DevTools → Lighthouse) with **Accessibility** selected. Confirm the accessibility score is **≥ 90**. Address any automated findings (color contrast, label coverage, heading hierarchy).
